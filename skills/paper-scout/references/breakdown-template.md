# 拆解模板

## 论文条目格式

```markdown
### [标题](arXiv链接) （YYYY-MM，类别）
- 一句话：做了什么、给谁用
- 问题动机：现有方法缺什么
- 核心方法：2–3 个关键组件/机制，避免堆术语
- 关键结果：数据集 + 代表性数字（必须来自摘要/正文，不得虚构）
- 局限：作者承认的 + 你观察到的
- 与用户方向的关系：可借鉴点 / 可跟进的开放问题
```

## 项目条目格式

```markdown
### [owner/repo](链接) ★约N · 最近更新 YYYY-MM
- 定位：解决什么问题，对标哪个同类项目
- 架构要点：入口 → 核心模块，一层即可
- 成熟度：release 节奏、文档、issue 活跃度
- 上手成本：依赖、是否需要 GPU/API key
- 与论文的关系：对应论文链接（如有）
```

## 写作规则

- 每条必须带可点击链接；数字（star、日期、指标）只写检索到的，写不出来的删掉。
- 只读过摘要时在该条末尾加"（仅基于摘要）"。
- 趋势小结不逐条重复，只写跨条目的共性：热点方法、常见 benchmark、正在退场的做法。
- 中文输出，论文标题保留英文原名。
