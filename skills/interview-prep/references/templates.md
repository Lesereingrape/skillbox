# 准备.md 结构模板

文件名固定六段，生成/更新时保持段号不变，段内按需增删条目。

```markdown
# {公司} · {岗位} 面试准备 v{n}
更新：YYYY-MM-DD ｜ 面经样本：{i} 份 ｜ 命中率：{k}/{m}（仅复盘后填）

## 0. 岗位定位一句话
这个岗位在招什么人 + 我的一句话匹配主张（用真实经历，不夸大）。

## 1. 项目深挖（简历驱动，最高优先级）
每个被写进简历的项目一节：
- 30 秒版 / 3 分钟版讲法（背景→我的角色→关键决策→量化结果）
- 追问树：技术选型（为什么 X 不 Y）→ 踩坑与解法 → 指标怎么算的 → 规模×10 怎么改
- 证据清单：可展示的截图/数据/代码位置
规则：写进简历的每个词都可能被挖；答不上来的先标记"高危"。

## 2. 岗位要求知识点（JD 驱动）
| 知识点 | 优先级 | JD 依据（摘录原句） | 状态 |
|---|---|---|---|
状态 ∈ 未准备 / 学习中 / 能讲清 / 已提问过（面经命中）。

## 3. 领域基础与热点
该方向公认基础题（如 Transformer、RAG、评测方法）+ 近半年热点，每条给"一句话答案 + 深入一层答案"。

## 4. 题库（面经/真题召回）
| 题目 | 频次 | 来源 | 状态 |
|---|---|---|---|
来源写 M{i}（面经编号）或"本人实录"；状态 ∈ 未练 / 已练 / 答得不好（附一句话复盘）。

## 5. 向面试官反问
按"技术成长 / 团队与业务 / 流程"各 1–2 条，全部要基于第 2 节 JD 分析得出，不写通用空话。

## 6. 变更记录
v{n}（日期）：本次改动摘要，如"3 条高频题升级为必问；新增 XX 知识点（M4 面经来源）"。
```

# 面经.md 台账模板

每份面经一个块，编号递增且不复用：

```markdown
## M{i} {公司}/{岗位} · {轮次} · {日期} · {渠道或链接}
- 考察重点：
- 题目清单：
  - Q1 …（标注对应准备条目：§2-xx / §4 新增 / 未覆盖）
- 主观信息：面试官风格、追问深度、HR 关注点
```

# 优先级判定规则

- 跨面经相似题出现 ≥2 次 → 第 4 节频次+1 且状态列置顶为"必问"，同步提升第 2/3 节对应知识点优先级。
- 面经与 JD 冲突时以面经为准（真实考什么 > 招聘文案）。
- 单次提及且边缘 → 记录但不升级；连续两份面经无涉及的 JD 重点可在变更记录中提示风险。
- 本人实录（自己刚面完）权重最高：无论频次，答得不好的题必须进第 4 节并写一句话复盘。
