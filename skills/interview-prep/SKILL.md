# Interview Prep — 简历+JD 驱动、面经迭代的面试准备

## Overview

一个岗位一个目录：`面试准备-{公司}-{岗位}/`，内含 `准备.md`（主文档，带版本号）和 `面经.md`（台账）。结构与优先级规则全部遵循 `references/templates.md`。

## 路径 A：首次准备（还没有目录）

1. 收齐三样输入，缺哪问哪（一次问全，不要挤牙膏）：
   - 简历：文本/文件/PDF 路径（PDF 直接用 Read 读）；
   - 项目描述：用户口述或仓库路径；
   - JD：粘贴文本或链接（链接用 WebFetch 抓）。
2. 创建目录，按模板生成 `准备.md` v1：
   - 第 1 节项目深挖是重心：每个简历项目列追问树，凡是简历里写不出量化依据或答不上来的词，标"高危"提醒用户补。
   - 第 2 节逐条对应 JD 原句，不写 JD 没要求的泛泛八股。
   - 第 3 节只放该方向公认必考 + 近半年热点，凭检索补充时用 WebSearch 并给链接。
   - 第 5 节反问必须从 JD 与用户职业诉求推导。
3. `面经.md` 建空台账，写一行"暂无样本，v1 基于 JD 推断"。
4. 输出：文件路径 + 3 条最重要的准备建议（含高危项），不要把全文贴回对话。

## 路径 B：面经投喂 / 面试实录（已有目录）

1. 新面经（他人面经、链接、截图转述）或用户说"今天被问了…" → 按模板追加 `M{i}` 块，来源、轮次、日期记全；链接原文用 WebFetch 取证后再提取，抓不到标注"用户转述"。
2. 逐题映射到 `准备.md`：命中现有条目的更新频次与状态；未覆盖的新增进第 4 节；按模板"优先级判定规则"升降级。
3. `准备.md` 版本号 +1，变更记录写清本次升降级条目；同步刷新头部"面经样本"计数。
4. 本人实录优先处理：答得不好的题一句话复盘写进状态列，并在对话里单独提示这条。
5. 汇报格式：一行总结（新增/升级/降级了什么）+ 当前 top3 必问，不贴全文。

## 通用规则

- 只基于用户真实简历与面经内容生成，禁止虚构"你做过 X"；材料没说的写入"待补充"。
- 多岗位共用知识点用相对链接引用首个岗位的 `准备.md` 对应节，不复制正文。
- 用户要模拟追问/压力面演练 → 交给 `/interview`（asu-skills）类技能，本技能只管知识准备与台账维护。
- 目录默认建在当前工作目录；用户指定位置则从其指定。
